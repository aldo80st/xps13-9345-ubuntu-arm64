# XPS AUTHZ v1.1 — fixed native read-only inspection

Candidate for the trusted host-inspector adapter. No privileged CLI, module control, service activation, workload, writes, or general command runner. The non-root snapshot can be exercised on XPS without a grant; it does not demonstrate privileged G-AUDIT or R0 acceptance.

Pinned Dell XPS 13 9345 / aarch64 / 7.3.0-11-generic, stock compressed Iris module hash and srcversion, 59 exact thermal zone names observed 2026-11-24. Read every sensor and both external-power flags and actual energy-based battery percentage, fail closed on missing/duplicate/unknown sensors or invalid samples. Conservative max across all non-battery zones; exact thresholds in contract. Device nodes are located by names, driver identity, sysfs device number and character-device stat, not fixed minor indices. Official module and boot files are hashed through anchored directory descriptors along fixed canonical paths, with root ownership and no group/other write at every ancestor; inaccessible boot files yield UNKNOWN. Audit refuses CAP_SYS_MODULE, but syscall isolation still needs native unit acceptance.

Process visibility helper is read-only, root/CAP_SYS_PTRACE and an independently established root-protected owner-issued per-boot HostWitness are required; compare boot ID, PID namespace, full proc/sysfs mounts and scan every thread's fd metadata within fixed bounds; non-root, missing witness or partial visibility is UNKNOWN; an absent module also requires the witness and a full sysfs view. It cannot prevent races with later device opens, so R0 still needs fresh refcount/holders and non-force unload under policy commitment. Do not pass untrusted Reader, filesystem path, UID or fixture from IPC into a privileged worker. No installation or live effects. Independent review and native acceptance gates remain.
