### Revisión de seguridad de scripts de referencia

Se inspeccionaron **sin ejecutarlos** los scripts `01-fix-cdsp-firmware.sh`, `02-stage-dsp-files.sh`, `03-boot-reliability.sh`, `04-verify-npu.sh`, `05-run-llm-on-npu.sh` de `UnsignedChad/t14s-x1e-npu`:

- `01` sustituye firmware en ruta **Lenovo**, asume partición y rutas fijas. **No aplica a Dell y se prohíbe su ejecución.** La rama HAMOA-1 ya se observó en el firmware Dell.
- `02` ejecuta como root, monta un volumen, copia binarios DSP y arranca `cdsprpcd`. No debe reutilizarse sin adaptar rutas/procedencia, licencia y rollback.
- `03` instala un servicio de apagado y escribe estados `remoteproc`. Su efecto sobre estabilidad y orden de apagado requiere diseño/revisión específica.
- `04` inicia un servicio y realiza pruebas reales; captura salidas con `grep ... || true`. El exit code puede quedar oculto; **no usarlo como veredicto automático de PASS**.
- `05` arranca servicio y ejecuta Genie; para generar contexto LLM cita compilación en host x86 y SDK compatible. No asumir que ya existen modelos listos.

## M1-B — Ruta documentada para FastRPC y shells (solo lectura)

**Nuevo hallazgo:** El repositorio oficial [qualcomm/fastrpc](https://github.com/qualcomm/fastrpc) documenta build nativo Linux y acceso de dispositivos `root:fastrpc` con reglas udev `0640`, además de permisos sobre `/dev/dma_heap/system`. **Esto describe el diseño upstream, no el estado actual del XPS**, cuyos nodos siguen en `0600 root:root`. La instalación y gestión de grupos/permisos requerirán aprobación específica.

**Origen de shells candidato:** `linux-msm/hexagon-dsp-binaries` mantiene entradas `x1e80100/Qualcomm/Hamoa-IoT-EVK/CDSP.HT.2.9.c1-00082-HAMOA-1` y `...-00094-HAMOA-1`, con `fastrpc_shell_3` y `fastrpc_shell_unsigned_3`. El registro [WHENCE](https://github.com/linux-msm/hexagon-dsp-binaries/blob/trunk/WHENCE) las clasifica `Redistributable` sujeto a `LICENSE.qcom-2`, con URL de origen Qualcomm. El [config.txt](https://github.com/linux-msm/hexagon-dsp-binaries/blob/trunk/config.txt) escoge `-00094` para el kit Hamoa-IoT-EVK. **No** se verificó compatibilidad con la imagen Dell `-00046`; coincidencia de rama `c1/HAMOA-1` es necesaria pero no prueba suficiente.

**Mitigación propuesta:** investigar primero FastRPC oficial más shells redistribuibles de Qualcomm, sin alterar firmware Dell ni depender de copiar controladores Lenovo. Si se obtienen los binarios, documentar versión, SHA256, licencia y cadena de procedencia. Planificar pruebas controladas de apertura de sesión antes de desplegar un runtime LLM.

**Riesgo persistente:** el repositorio upstream `qualcomm/fastrpc` mantiene [#377](https://github.com/qualcomm/fastrpc/issues/377) abierto. No ejecutar todavía la ruta llama.cpp/dspqueue. Ningún binario fue descargado, compilado ni ejecutado para esta revisión.

**Reevaluación del bloqueo Q-002:** se identificó una **fuente candidata**, pero **Q-002 continúa pendiente** hasta que exista evidencia de compatibilidad concreta con Dell y revisión de las condiciones legales.

## M1-C — Compatibilidad de firmware, permisos y ruta de adquisición (solo lectura)

### Hallazgo determinante: firmware Dell `-00046` frente a shells genéricos `-00082/-00094`

- **Observado en el host:** `QC_IMAGE_VERSION_STRING=CDSP.HT.2.9.c1-00046-HAMOA-1`.
- **Fuente `linux-msm/hexagon-dsp-binaries`:** shells CDSP `CDSP.HT.2.9.c1-00082-HAMOA-1` y `-00094-HAMOA-1` para **Hamoa IoT EVK**, no específicamente para la XPS. Su registro `config.txt` elige `-00094` para ese EVK.
- **Verificador oficial:** `qualcomm/fastrpc/test/fastrpc_healthcheck.c` normaliza los identificadores y exige `strcmp(fw_id, sh_id) == 0` (línea 427 de la versión revisada), no solo coincidencia de rama. El documento `fastrpc-healthcheck_doc.md` también requiere un build ID coincidente. Esta es la política del **diagnóstico**, no prueba suficiente de que un shell `-00094` necesariamente falle con firmware `-00046` en tiempo de ejecución. **No se ha probado.**
- **Fuente Dell:** [firmware-dell-qcom](https://github.com/valpackett/firmware-dell-qcom/blob/trunk/README.md) conserva firmware XPS de Dell, pero su árbol inspeccionado no incluye shells FastRPC. También existen [paquetes oficiales de controladores Dell para XPS 9345](https://www.dell.com/support/kbdoc/en-us/000226164/xps-13); todavía no se identificó un paquete con shell **del mismo build que el firmware instalado**.
- **Conclusión:** rechazar inferir compatibilidad solo por `c1/HAMOA-1`; preferir localizar un shell `-00046` procedente del proveedor/modelo o confirmar experimentalmente una alternativa bajo protocolo autorizado. **No sustituir firmware Dell para hacer coincidir una shell genérica.**

### Avance tangible: FastRPC upstream incluye servicio, permisos y verificador

Se verificó en [qualcomm/fastrpc](https://github.com/qualcomm/fastrpc/tree/main) (revisión `d247519650fe5cb16de6c78edaa95bcc4be25073`; release publicada `v1.0.8`):

- Servicio systemd: `files/cdsprpcd.service.in`; daemon: `src/dsprpcd.c`; reglas: `files/60-fastrpc.rules`; definiciones de grupo: `files/fastrpc.conf`.
- Diagnóstico existente: `test/fastrpc_healthcheck.c` y [descripción de estados Online vs Offload-Capable](https://github.com/qualcomm/fastrpc/blob/main/test/fastrpc-healthcheck_doc.md).
- Configuración por máquina: [Docs/conf_guideline.md](https://github.com/qualcomm/fastrpc/blob/main/Docs/conf_guideline.md) define YAML bajo `/usr/share/qcom/conf.d/` y `DSP_LIBRARY_PATH` relativo a `/usr/share/qcom/`. No es imprescindible escribir un daemon ni crear un sistema de configuración nuevo.
- **Inconsistencia por evaluar:** las reglas publicadas establecen `MODE="0640"` para nodos FastRPC (lectura de grupo) aunque el README dice que un grupo tiene acceso de lectura/escritura. Confirmar los modos de apertura que requieren las aplicaciones antes de adoptar reglas o ampliar permisos. Las reglas agregan ACL de grupo sobre `/dev/dma_heap/system`.
- **Host Dell:** actualmente no existe grupo `fastrpc`, no hay reglas udev FastRPC, y los nodos FastRPC y `/dev/dma_heap/system` se observaron `0600 root:root`. No se modificaron.

### QAIRT Linux ARM64: contenido confirmado, no ejecutado

En [qualcomm/geniex-qairt-plugin](https://github.com/qualcomm/geniex-qairt-plugin/tree/main/third-party/linux-gcc11.2) (revisión `dfa72638bd24d92c0e2179e431dd6dcb6a271fa2`) se publican las bibliotecas QAIRT **2.50.40.260831** `libQnnHtp.so`, `libQnnHtpV73Stub.so`, `libQnnHtpV73Skel.so` y `libQnnSystem.so`, entre otras. **No** equivalen a un stack FastRPC completo ni se comprobaron en XPS. Se exige revisar [THIRD_PARTY_NOTICES.md](https://github.com/qualcomm/geniex-qairt-plugin/blob/main/THIRD_PARTY_NOTICES.md), porque las librerías tienen EULA distinta de la licencia BSD del plugin.

### Decisión operacional: M2 permanece bloqueado

**Paso siguiente permitido sin alterar el sistema:** localizar en una fuente oficial o paquete Dell un shell FastRPC cuyo build ID corresponda a la imagen `-00046` observada; registrar hash, procedencia, licencia y compatibilidad declarada. Si no existe, presentar alternativas con riesgos para aprobación operativa separada. Solo entonces preparar instalación FastRPC en espacio usuario, `fastrpc-healthcheck`, prueba calculadora y `qnn-platform-validator` por ese orden. No activar `cdsprpcd`, grupos, ACL, contenedores privilegiados ni pruebas NPU por la aprobación documental actual.

## M1-D — Ruta prioritaria hacia un shell Dell de procedencia verificable

**Fecha de análisis:** 2026-11-05. **Tipo:** investigación estática/documental; sin cambios en la XPS.

### Fuente OEM identificada

El [Qualcomm Chipset Driver de Dell, identificador TJ10M](https://www.dell.com/support/home/en-us/drivers/driversdetails?driverid=tj10m), es una publicación oficial compatible con XPS 13 9345 y Windows ARM64:

| Campo | Valor publicado por Dell |
| --- | --- |
| Archivo | `Qualcomm-Chipset-Driver_TJ10M_WINARM64_2.1.0.66_A17.EXE` |
| Versión | `2.1.0.66, A17` |
| Fecha | `2025-12-15` |
| Tamaño publicado | `52.09 MB` |
| SHA-256 publicado | `4e4541e60e20a42c05ab9c011293a449cc47a3735054efd92cf4f3b31120c9ee` |
| Descarga OEM | `https://dl.dell.com/FOLDER13768743M/1/Qualcomm-Chipset-Driver_TJ10M_WINARM64_2.1.0.66_A17.EXE` |

La publicación de [firmware-dell-qcom](https://github.com/valpackett/firmware-dell-qcom/blob/trunk/README.md) identifica la versión Dell `2.1.0.66 A17` como procedencia de firmware XPS, pero **su árbol no incluye** `fastrpc_shell_3` ni `fastrpc_shell_unsigned_3`.

**Alcance de la evidencia:** Dell confirma que existe el paquete OEM y su suma de integridad; **NO** está verificado que el EXE contenga un shell CDSP o que coincida exactamente con el firmware cargado `CDSP.HT.2.9.c1-00046-HAMOA-1`. Se intentó descargar el paquete en el entorno de análisis, pero falló la transferencia; no se obtuvo archivo ni se calculó un hash propio. No se montó la partición de Windows ni se tocó el sistema de la XPS.

### Procedimiento de admisión estática, sin ejecución del instalador

1. Obtener una copia del instalador **solo de Dell**. Verificar SHA-256 contra el valor publicado; **rechazar** si no coincide.
2. Inspeccionar como **archivo de datos**, sin ejecutar `.EXE` y sin instalar controladores Windows: índice del contenedor, ruta `CDSP`, archivos `fastrpc_shell_3` y `fastrpc_shell_unsigned_3`, así como versiones y cadenas `CRMBuilds/`.
3. Comparar el **build ID completo** de cada shell con `CDSP.HT.2.9.c1-00046-HAMOA-1`, no únicamente la rama `HAMOA-1`. Registrar procedencia y suma SHA-256 individual del shell en el informe, **no copiar blobs a Git**.
4. Si no aparece shell con build compatible, registrar un **No-Go de adquisición** y evaluar los paquetes oficiales Dell anteriores u otra vía OEM, sin forzar firmware genérico ni shells de otro modelo.
5. Si se identifica una coincidencia, someter a revisión independiente las restricciones de licencia, superficie de permisos y protocolo de recuperación DSP **antes** de proponer instalación en Ubuntu.

### Evidencia complementaria, no sustituto OEM

Una publicación técnica externa para otro equipo X Elite ([Demain Portal NPU Runtime](https://docs.demain.technology/wiki/21-npu-runtime-safe-rust-wrappers-for-qualcomm-hexagon-fastrpc/)) afirma usar firmware `CDSP.HT.2.9.c1-00046-HAMOA-1` y un shell proveniente de un paquete **HP**. Esto sugiere que existen shells de esa familia, pero **no demuestra compatibilidad con la Dell ni autoriza reutilizar firmware o shells HP**.

### Puertas operativas para cerrar M1 y abrir M2

- **G1 — adquisición:** shell identificado y procedencia legal documentada; hash del paquete y del shell comprobados.
- **G2 — compatibilidad:** coincidencia de build IDs o evidencia específica equivalente, sin sustituir firmware Dell.
- **G3 — permisos:** revisar `fastrpc` oficial, nodos `0600 root:root` observados, reglas udev `0640` y `/dev/dma_heap/system` sin asumir acceso de escritura.
- **G4 — seguridad:** plan de reversión y recuperación ante bloqueos FastRPC; excluir ejecución incontrolada, `SIGKILL` sobre RPC activo, servicios privilegiados permanentes y acceso a volúmenes Windows.
- **G5 — autorización:** las pruebas M2 se realizan **solo tras aprobación operativa específica**; la aprobación arquitectónica no las incluye.
